# OpenWhispr feature and architecture audit

Research date: 2026-09-09

## Scope

This audit compares OpenWhispr at commit [`058754a`](https://github.com/OpenWhispr/openwhispr/commit/058754a75d52a0fe46a5d855c1e7cb965a6fdd70), committed on 2026-09-09, with OpenYap at commit [`6acc3f6`](https://github.com/pabumake/openyap/commit/6acc3f67a133706cf66ec9009c4344df90831159), also committed on 2026-09-09. It uses first-party source code, repository documentation, and NVIDIA's model card. It is a source audit, not a hands-on product test.

## Conclusion

OpenWhispr is broader than OpenYap. Its current product includes desktop dictation, translation, an AI assistant, meeting capture, notes, audio import, local and cloud models, account sync, team sharing, enterprise policy, an API, and MCP access. OpenYap should not treat that breadth as a parity checklist. Most of it would weaken the current Apple-native dictation focus before the core experience is mature.

The part worth following now is OpenWhispr's local speech model workflow. It has a catalog, visible download state, disk checks, cancellation, installed-model selection, deletion, runtime prewarming, and engine-specific failure handling. Its Parakeet support also answers an important terminology question. OpenWhispr does not accept an arbitrary Hugging Face speech model. It recognizes catalogued model identifiers and, for Parakeet TDT 0.6B v3, downloads a fixed INT8 sherpa-onnx package from a k2-fsa GitHub release.

OpenYap can make that workflow smaller and more trustworthy. Keep Apple Speech as the zero-setup default. Add Parakeet TDT 0.6B v3 as the first optional speech model through a curated catalog. Pin every package to a digest and declare its source, license, languages, required runtime, installed size, and compatibility. Do not promise generic Hugging Face compatibility until the app can validate a precise package contract.

## How OpenWhispr structures local speech models

OpenWhispr is an Electron application with a React renderer and Node main process. The renderer calls a preload IPC interface for Whisper and Parakeet operations. The main process owns separate `WhisperManager` and `ParakeetManager` instances and registers their sidecar shutdown handlers. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/package.json#L1-L32) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/preload.js#L388-L461) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/main.js#L420-L478) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/main.js#L563-L570)

The Parakeet path has four distinct pieces:

1. A checked-in registry describes allowed model identifiers, display metadata, language coverage, approximate size, download URL, and extraction directory. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/models/modelRegistryData.json#L2-L118)
2. `ParakeetManager` rejects identifiers outside that registry, manages the downloaded package, and exposes status, deletion, diagnostics, and prewarming. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L25-L64) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L78-L138) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L523-L611)
3. The manager validates the extracted directory by checking for `encoder.int8.onnx`, `decoder.int8.onnx`, `joiner.int8.onnx`, and `tokens.txt` for transducer models. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeetModelInfo.js#L1-L35) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L420-L472)
4. A bundled sherpa-onnx websocket server loads those files. OpenWhispr converts input to mono 16 kHz WAV, sends float samples to the loopback server, splits long offline audio into 15 second segments, and retries an audible segment once if decoding returns no text. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeetWsServer.js#L113-L155) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeetServer.js#L21-L41) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeetServer.js#L67-L166)

This is catalog compatibility, not general Hugging Face compatibility. Whisper entries point at fixed Hugging Face files. Parakeet TDT points at a fixed k2-fsa archive. The manager admits only registry identifiers and specific file layouts. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/models/modelRegistryData.json#L3-L38) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/models/modelRegistryData.json#L140-L190) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L37-L64)

## Parakeet TDT 0.6B v3 as OpenYap's first optional model

NVIDIA describes Parakeet TDT 0.6B v3 as a 600 million parameter ASR model for 25 European languages. It detects the audio language and emits punctuation and capitalization. NVIDIA publishes it under CC BY 4.0. English and German are both in its supported set. [Source](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3/blob/main/README.md#model-card-for-parakeet-tdt-06b-v3)

OpenWhispr's package is not the original Hugging Face repository layout. It is a 680 MB INT8 conversion published by k2-fsa for sherpa-onnx. That distinction matters for OpenYap. The selectable item must identify both the upstream model and the exact runtime package the app knows how to load. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/models/modelRegistryData.json#L3-L38)

The OpenWhispr implementation is a useful feasibility proof for a local Mac process, but its Electron IPC and child-process websocket arrangement does not fit OpenYap's accepted native-client decision by default. OpenYap should first compare a direct Swift-compatible runtime integration with a packaged helper process. Either design must keep the runtime behind one speech engine contract so the dictation session does not know whether Apple Speech or Parakeet produced its final segments. [OpenYap's native-client decision](https://github.com/pabumake/openyap/blob/6acc3f67a133706cf66ec9009c4344df90831159/docs/adr/0004-keep-native-apple-clients.md#L18-L43)

## What OpenYap should borrow

### A real speech engine boundary

The existing `AppleSpeechEngine` callback supplies text plus an `isFinal` flag, which already resembles the volatile-segment and final-segment vocabulary. Preserve that stream contract, but move capture ownership and engine behavior behind an interface. Engine identity, model identity, locale support, preparation progress, and failure reason must be data, not conditionals scattered through `AppModel`. [Source](https://github.com/pabumake/openyap/blob/6acc3f67a133706cf66ec9009c4344df90831159/OpenYap/Speech/AppleSpeechEngine.swift#L26-L40) [Source](https://github.com/pabumake/openyap/blob/6acc3f67a133706cf66ec9009c4344df90831159/CONTEXT.md#L47-L101)

### The complete model lifecycle

The first app-managed model needs explicit states for not installed, downloading, installing, ready, active, incompatible, corrupt, and failed. The user must see progress, required disk space, installed size, and a cancellable download phase. Installation and active-model switching need separate commit points. An interrupted download must not become a selectable model. OpenWhispr handles much of this and is particularly careful not to replace a newer pending model selection when an older download finishes. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/components/onboarding/ProviderSetupStep.tsx#L695-L804)

### Runtime resilience that feeds OpenYap's session model

Silence detection, process startup timeout, health checks, long-input segmentation, retry of an empty decode for audible speech, and a visible partial result are all worth retaining as requirements. OpenYap already defines a partial result and says useful partial text survives interruption. Engine failures should report into that model rather than inventing a parallel state machine. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeetServer.js#L99-L166) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L289-L315) [Source](https://github.com/pabumake/openyap/blob/6acc3f67a133706cf66ec9009c4344df90831159/docs/domain/dictation-lifecycle.md#L1-L15)

## Where OpenYap can do better

### Verify model packages cryptographically

OpenWhispr's common downloader checks transfer completeness against HTTP length or an expected size, and its Parakeet installer checks free space and required filenames. The audited model registry has no digest field, and the Parakeet download path does not compute a content hash before extraction. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/downloadUtils.js#L46-L151) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/downloadUtils.js#L214-L289) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/parakeet.js#L346-L414)

OpenYap should require a pinned SHA-256 digest for each archive and verify it before extraction. The catalog should also record the upstream model URL, packaged-runtime URL, package version, license and attribution text, exact installed file contract, supported architectures, minimum OS, languages, and expected bytes. A signed remote catalog may come later. The first release can ship its catalog inside the signed app.

### Make privacy statements mechanically true

OpenWhispr's README says "No data collection, no telemetry," while the same commit exposes an opt-in setting described as sharing anonymous timing and error data. The setting defaults off, but the two first-party descriptions still conflict. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/README.md#L30) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/stores/settingsStore.ts#L1373-L1379) [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/locales/en/translation.json#L2393-L2400)

OpenYap should keep the simpler statement already enforced by ADR 0001. Speech and formatting stay on device, the app has no account requirement, and loss of network access after asset installation cannot block dictation. Model downloads are the only new network event in this effort. The app should show the host and size before starting one. [Source](https://github.com/pabumake/openyap/blob/6acc3f67a133706cf66ec9009c4344df90831159/docs/adr/0001-on-device-processing-and-local-retention.md#L12-L32)

### Keep session semantics deeper than the engine

OpenWhispr's shared dictation lifecycle has four states: idle, preparing, recording, and processing. OpenYap separately models capture, finalization, text preparation, delivery, retry, cancellation, failure, and awaiting delivery under a session identifier. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/helpers/dictationLifecycle.js#L1-L22) [Source](https://github.com/pabumake/openyap/blob/6acc3f67a133706cf66ec9009c4344df90831159/docs/domain/dictation-lifecycle.md#L5-L37)

Do not let model selection collapse those semantics into a generic success or error callback. A speech engine must report final segments, partial results, cancellations, and failures without deciding whether prepared text was delivered. This keeps the same contract usable by the later iOS capture host and keyboard delivery agent.

### Show evidence, not generic quality labels

OpenWhispr's catalog describes Whisper models with labels such as "Good balance" and "Best quality, slowest." It does not expose app-specific measurements. [Source](https://github.com/OpenWhispr/openwhispr/blob/058754a75d52a0fe46a5d855c1e7cb965a6fdd70/src/models/modelRegistryData.json#L140-L190)

OpenYap should benchmark Apple Speech and Parakeet on the same English and German dictation fixture set and publish measured cold-start time, warm latency, real-time factor, peak memory, package size, and word error rate. The picker can then explain why a user might choose each engine on the target Mac instead of repeating upstream marketing.

## Recommended boundary for the next decision

The next design ticket can assume this scope:

- Apple Speech remains installed by the operating system and selected by default.
- Parakeet TDT 0.6B v3 is the first app-managed optional speech model.
- "Hugging Face compatible" means the catalog may cite or download a fixed artifact hosted on Hugging Face. It does not mean arbitrary repository import.
- Every app-managed item binds a speech model, a package format, a runtime, a digest, and compatibility metadata.
- Speech engine choice does not change smart formatting, correction rules, snippets, delivery, or history semantics.
- No local engine may fall back to cloud processing.
- More Whisper, Parakeet, or other models enter the catalog only after the same package and benchmark checks pass.

This gives OpenYap the useful part of OpenWhispr's model choice without importing its cloud product, account system, Electron orchestration, or unrelated meeting and notes scope.
